# Telegram Mini App

Приложение для «Ярмарки украденной магии»: сервер хранит состояние игры и проверяет каждое действие, клиент показывает игрокам и ведущему их экраны внутри Telegram.

## Что здесь лежит

Четыре пакета в одном pnpm-воркспейсе:

- `packages/shared` (`@fair/shared`) — правила игры без ввода-вывода: типы, команды и события, чистые функции `decide` (проверяет команду и возвращает события), `reduce` (применяет событие к состоянию) и `execute` (обе сразу), проекции состояния для игрока и ведущего.
- `packages/server` (`@fair/server`) — Fastify, WebSocket, SQLite, вход через Telegram, бот.
- `packages/client` (`@fair/client`) — Vite и Preact, экраны игрока и ведущего.
- `packages/sim` (`@fair/sim`) — симулятор вечера: боты проходят три акта против настоящего сервера и проверяют результат ([README](packages/sim/README.md)).

Сквозной тест лежит в `e2e/`.

## Установка

Нужны Node 20 и pnpm 9.

```sh
pnpm install
```

## Запуск в разработке без Telegram

Вход через Telegram в разработке заменяет «ручной» вход по коду. В первом терминале запустите сервер:

```sh
cd packages/server
DB_PATH=./data/dev.sqlite ALLOW_DEV_AUTH=1 SESSION_SECRET=dev pnpm exec tsx src/index.ts
```

Во втором терминале запустите клиент:

```sh
pnpm --filter @fair/client dev
```

Vite проксирует `/api` и `/ws` на `localhost:8080`. Если сервер слушает другой порт, задайте его переменной `API_PORT` при запуске клиента, например `API_PORT=8091 pnpm --filter @fair/client dev`. Это переменная Vite, а не сервера, поэтому в `.env.example` её нет.

Код ведущего сервер печатает в лог при старте строкой «Код ведущего». Коды ведущего и всех ролей также отдаёт `GET http://localhost:8080/api/dev/codes` (только при `ALLOW_DEV_AUTH=1`).

Ссылка для входа выглядит так:

```
http://localhost:5173/?dev=<число>&code=<код>
```

`<число>` — любой выдуманный идентификатор пользователя (у каждого открытого окна свой), `<код>` — код ведущего или роли. Окна разных людей открывайте в разных профилях браузера или в приватных окнах. `ALLOW_DEV_AUTH=1` нельзя включать на настоящей игре.

## Переменные окружения

Скопируйте `.env.example` в `.env` и заполните:

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | токен бота от BotFather; без него сервер не стартует, если не включён `ALLOW_DEV_AUTH=1` |
| `BOT_NAME` | имя бота без `@`, из него строятся ссылки-приглашения |
| `SESSION_SECRET` | секрет подписи сессий, случайная длинная строка |
| `CLIENT_URL` | адрес клиента, который открывает бот |
| `DB_PATH` | файл SQLite (`:memory:` для тестов) |
| `CONTENT_PATH` | файл с данными игры; по умолчанию `docs/design/game-data-v0.2.json` |
| `PORT` | порт сервера, по умолчанию 8080 |
| `ALLOW_DEV_AUTH` | `1` включает вход по коду без Telegram, только для разработки; с ним `GET /api/health` отдаёт ещё и память сервера (`memory: { rss, heapUsed }`) |
| `BOT_POLLING` | `1` запускает бота в режиме опроса |

Токены и секреты в Git не кладите.

## Проверки

```sh
pnpm test        # модульные тесты всех пакетов
pnpm typecheck   # проверка типов
pnpm e2e         # сквозной тест в браузере
pnpm sim -- --players 30 --seed 7   # прогон вечера на 30 ботов, отчёт в packages/sim/sim-out
pnpm sim:load -- --players 30 --minutes 10 --seed 1    # нагрузка: 30 ботов 10 минут
pnpm sim:load -- --players 30 --minutes 120 --seed 1   # нагрузка на всю длину вечера
pnpm sim:bench   # время сборки проекций на 30 игроков при 0, 2000 и 8000 предложений, без сервера
```

`pnpm test` включает тест вечера: 12 ботов проходят вечер от состава до показа итогов против сервера, поднятого в процессе. Прогон на 30 в `pnpm test` не входит, его запускают `pnpm sim`. `pnpm sim:load` держит ярмарку в акте I, каждый бот делает ход примерно раз в 10 секунд, а прогон меряет задержки, размеры проекций и память сервера; отчёт `packages/sim/sim-out/load-<игроков>-<минут>.md`, при нарушении критериев код выхода 1. Двухчасовой прогон стоит повторить перед праздником. Параметры и проверки описаны в [README симулятора](packages/sim/README.md).

Для `pnpm e2e` Playwright сам поднимает сервер (порт 8091, база в памяти) и клиент (порт 5191). Если браузера нет, один раз выполните `pnpm exec playwright install chromium`. Тест проходит весь путь: ведущий собирает состав на 12 и открывает ярмарку, Грета покупает пыль, создаёт Фокус силы и продаёт его Серафине, Серафина принимает сделку.

## Что входит в эту версию

Вход, соединение с сервером в реальном времени, экраны игрока (роль, сумка, сделки, мастерская, алтари, события, итоги) и ведущего (состав, пульт, итоги), серверная проверка команд, способности, лоты, закрытие ярмарки и выгрузка журнала. Подготовка к живому вечеру (этап 7, [спецификация](../../docs/superpowers/specs/2026-10-27-live-night-design.md)):
- ведущий отмечает опоздавших и ушедших и после открытия;
- код ведущего пересдаётся с сервера (`DEPLOY.md`, «Пересдача кода ведущего»);
- на паузе сделки стоят;
- содержимое игры приходит ведущему один раз при подключении;
- проекции не растут со временем: ведущий получает ожидающие сделки и последние 100 обменов, игрок свои ожидающие сделки и 20 последних закрытых;
- клиент сам переподключается и предлагает «Повторить» при неудачном входе.

Порядок вечера для ведущего описан в [памятке](../../docs/design/gm-runbook.md). Что вошло в первую версию и что отложено, описано в разделах 2 и 14 [спецификации](../../docs/design/mini-app-spec.md); порядок работ — в [плане](../../docs/superpowers/plans/2026-10-23-mini-app-core.md). Всё, что там отнесено к следующим этапам, здесь не реализовано.

## Развёртывание

Клиент и сервер должны быть на одном origin: клиент обращается к `/api/...` и `/ws` относительно своего адреса. Сборка и запуск:

```sh
pnpm install
pnpm --filter @fair/client build   # статика в packages/client/dist
cp .env.example .env               # заполнить BOT_TOKEN, BOT_NAME, SESSION_SECRET, CLIENT_URL
pnpm start                         # сервер на PORT (по умолчанию 8080)
```

`pnpm start` запускает `packages/server` через `tsx`, поэтому относительный `DB_PATH` (по умолчанию `./data/session.sqlite`) считается от `packages/server`. Лучше задать абсолютный путь.

Пример `Caddyfile` (домен и путь к репозиторию замените своими):

```
fair.example.org {
	handle /api/* {
		reverse_proxy localhost:8080
	}
	handle /ws {
		reverse_proxy localhost:8080
	}
	handle {
		root * /srv/halloween-2026/apps/mini-app/packages/client/dist
		try_files {path} /index.html
		file_server
	}
}
```

Caddy сам получит сертификат и проксирует WebSocket без отдельных настроек. `try_files` отдаёт `index.html` на любой путь клиента.

- Нужен HTTPS: Telegram открывает Mini App только по `https`. Проще всего поставить перед сервером Caddy, он сам получит сертификат.
- В BotFather создайте бота и задайте Main Mini App URL (адрес клиента, то есть `CLIENT_URL`). Ссылки-приглашения имеют вид `https://t.me/<бот>?startapp=<код>`.
- `BOT_POLLING=1` включает опрос Telegram без вебхука; для одного процесса этого достаточно.
- `ALLOW_DEV_AUTH` на проде держите равным `0`.

## Выгрузка журнала

Кнопка «Скачать журнал» на пульте открывает `/api/gm/export` с токеном ведущего. Ответ: журнал событий и состояние без Telegram id, привязок, кода ведущего и кодов приглашений, имя файла `evening-<дата по Москве>.json`. Тот же файл сервер сам пишет в `<папка DB_PATH>/exports/evening-<closedAt>.json` при закрытии ярмарки и перезаписывает при показе итогов и после каждого исправления. При `DB_PATH=:memory:` файл не пишется.

## Сброс

Перед новой игрой ведущий нажимает на пульте «Сбросить игру». Состав, привязки игроков и журнал удаляются, коды приглашений выдаются заново, ведущий остаётся привязанным. Ссылки, разосланные до сброса, перестают работать.

## Чего пока нет

- Двухчасовой прогон после этапа 8 показал, что рост задержки из-за закрытых сделок устранён: p50 со второй минуты держится в пределах 18–24 мс против 442 мс к 120-й минуте до правки. Но один выброс остался: в минуту 45 p95 был 702,7 мс, из-за него критерии нарушены. Причина не установлена, выброс проверяется повторным прогоном ([итоги](../../docs/superpowers/specs/2026-10-28-compact-offers-design.md), раздел 7).
- Движок хранит в состоянии ожидающие предложения и по 20 самых новых закрытых на каждого участника, полный список лежит в журнале событий. Обмены и записи действий не уплотняются, 8000 обменов добавляют около 1 мс на сборку проекций.
- На вкладке «Сделки» игрок видит только 20 последних закрытых сделок; более старые пропадают из списка.
- Структурные контакты и второй ведущий ([спецификация приложения](../../docs/design/mini-app-spec.md), §15–16), передача роли ведущего из интерфейса.
