# План этапа 6: прогон вечера, экспорт журнала, памятка ведущего

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Прогнать полный вечер на 12 и 30 ботов против настоящего сервера, починить найденное, дать ведущему выгрузку журнала и памятку для живого теста.

**Architecture:** Новый пакет `@fair/sim` (боты по WebSocket, детерминированный оркестратор, проверки, отчёт, тест вечера в процессе). Инварианты и `COMMAND_TYPES` переезжают в `@fair/shared`. Сервер получает маршрут выгрузки с чистой функцией очистки и автозапись при закрытии. Клиент получает кнопку выгрузки. Документация: памятка ведущего, обновления спецификации.

**Tech Stack:** TypeScript, pnpm workspace, `ws`, `tsx`, vitest, Fastify (сервер), Preact (клиент).

**Spec:** `docs/superpowers/specs/2026-10-27-evening-design.md` (разделы 2–7 обязательны, раздел 9 содержит принятые решения).

## Global Constraints

- Русский язык в интерфейсе, отчётах, документации и комментариях; идентификаторы на английском.
- Клиент (`packages/client/src`) импортирует из `@fair/shared` только типы; `@fair/sim` может импортировать значения.
- `@fair/shared` не читает файлы и не использует `node:*` вне `src/node.ts` и `__tests__`.
- Симулятор не использует `Math.random`; вся случайность из `Rng` с зерном.
- Симулятор никогда не посылает `session.reset`.
- Прогон падает с ненулевым кодом при любой непрошедшей проверке раздела 3 спецификации; пороги времени и размера только предупреждают.
- Правила игры не меняются; вопросы к правилам идут в раздел «Вопросы владельцу» отчёта.
- `docs/design/game-data-v0.2.json` и `docs/references` не меняются.
- Все команды фиксируются коммитами с автором и коммитером `Andrew Piskunov <45717261+andrewpiskunov@users.noreply.github.com>`, сообщения на русском, без упоминания инструментов и без `Co-authored-by`.
- В git не попадают `sim-out/`, базы `.sqlite`, выгрузки `exports/`, `.superpowers/`, `.playwright-mcp/`, `test-results/`.
- Перед каждым коммитом из `apps/mini-app`: `pnpm typecheck && pnpm test` зелёные (shared 376+, client 53+, server 42+, sim по мере появления).

## Review Focus

1. Проекции приходят асинхронно: сверка золота игрока с состоянием ведущего при разных `seq` даёт ложные падения → тест в T3: `waitSeq` ждёт у всех соединений `seq` последнего результата, и сверка после круга проходит на 12 ботах.
2. Просьба согласия закрывается сменой акта: если перед `act.next` не сделать круг ответов, способность с согласием «не сработала» и покрытие падает → тест в T3: после акта I все просьбы в состоянии `accepted`/`declined`, ни одной `expired` с причиной `act`.
3. Ставка ниже своей прежней даёт `invalid`: бот второй раз ставит выше или не ставит → тест в T2 (`policy`): при прежней ставке 2 и золоте 3 политика даёт 3 или `null`.
4. Выгрузка без личных данных: `telegramId` встречается в пяти местах (событие привязки, открытие ярмарки, сброс, состояние, привязки) → тест в T6 ищет каждый вымышленный id в строке выгрузки.
5. Автозапись при закрытии с `DB_PATH=:memory:` и при ошибке записи не должна ломать игру → тест в T6: при `:memory:` файла нет, при недоступной папке закрытие проходит, в консоли предупреждение.
