# Этап 5: закрытие ярмарки, исход, «Правда», цели — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** по кнопке ведущего заморозить ярмарку, посчитать алтари, исход, «Правду» и 60 целей, показать итоги игрокам и ведущему.

**Architecture:** чистая функция `computeClosing(state, content)` в движке считает результат по состоянию и двум новым журналам (`trades`, `crafts`); команда `session.close` закрывает всё открытое и кладёт результат в событие `FairClosed`; редьюсеры только копируют. Условия 60 целей лежат в коде (`goals.ts`) как каталог, аналогично `abilities.ts`. Клиент показывает цели с состоянием до закрытия (тем же вычислением через проекцию) и итоги после `session.reveal`.

**Tech Stack:** TypeScript, pnpm workspace `apps/mini-app` (`@fair/shared` движок, `@fair/server` Fastify+ws, `@fair/client` Preact+signals), vitest, Playwright e2e.

**Spec:** `docs/superpowers/specs/2026-10-27-closing-design.md` (далее «спецификация»; разделы 2–9). Проектные тексты исходов: `docs/design/magic-fair-v0.2.md`, раздел 7.

## Global Constraints

- Клиент импортирует из `@fair/shared` только типы (`packages/client/src/__tests__/type-only.test.ts`); константы для клиента копируются с комментарием «копия из …» или приходят в проекции.
- Редьюсеры детерминированы: не читают `random` и `now`; `FairClosed` и `Corrected` несут `closing` целиком, редьюсер копирует.
- `docs/design/game-data-v0.2.json` и `docs/references` не менять. Условия целей и тексты исходов живут в коде.
- Пороги алтаря: осколков с разными `ref` ≥ 3, Фокусов ≥ 2, золота ≥ 6, разных вкладчиков золотом ≥ 3. Готовых ≥ 2 → исход `'sleep'`, предупреждение в `warnings`.
- `session.close` только из `act3`, не во время торга (`biddingInProgress`); на паузе можно, `FairClosed` снимает паузу. `session.reveal` только из `closed`.
- После `closed`: все игровые команды (`offer.*`, `shop.*`, `altar.*`, `ability.use`, `item.use`, `consent.*`, `lot.bid`, `lot.buyout`, `player.chooseSide`, `act.next`, `clock.*`) → `phase`. Разрешены `gm.correct`, `gm.announce`, `gm.rebind`, `player.bind`, `player.setPresent`, `session.reveal`, `session.reset`.
- `player.chooseSide`: роль `side === 'free'`, фаза `act1 | act2`, один раз, сторона из `state.altars`.
- Условия: закрытый список `GoalCondition` спецификации §4.1 (21 вид), таблица §4.2 дословно, уточнения §4.2 (копия Астры не считается; `cleansed` любым зельем или `cleanseOther` с `removed.curse`; `cleanseOthers` требует `removed.curse || removed.thorns`; `exchanges` требует, чтобы обе стороны отдали золото, ингредиент или вещь; перековка считается изготовлением).

## Review Focus

1. Закрытие на паузе: часы не должны остаться «на паузе» навсегда, верхняя полоса показывает «Закрыто» без «пауза» → тест в задаче 3.
2. Два готовых алтаря по ошибке исправлений: исход `sleep`, предупреждение называет стороны, ведущий может забрать вещь с алтаря исправлением и получить пересчёт → тест в задаче 3.
3. Свободный без выбранной стороны при исходе своей «любимой» стороны достижения не получает; Марта видит выбранную сторону → тесты в задачах 2 и 3.
4. Просьба и предложение, висящие в момент закрытия: золото и вещи возвращаются, `abilityPending` снят, журнал применений не трогается → инварианты в задаче 3.
5. Клиент: игрок, открывший приложение после `reveal`, сразу видит «Итоги», а не «События»; игрок без выбранной стороны после закрытия не видит кнопку выбора → ручной прогон в задаче 5.
